# Testing a go-datastar integration

How this repo tests itself, and how to test your own DataStar handlers.

## The layers

| Layer        | Tool                                 | What it proves                                        |
| ------------ | ------------------------------------ | ----------------------------------------------------- |
| Wire format  | golden tests + testable examples     | patches render the exact upstream-compatible bytes    |
| Transport    | go-sse tests + `TestE2E_SSEHeaders`  | SSE headers, flush, heartbeat behavior                |
| E2E          | `datastartest`                       | real HTTP server → real SSE parsing → decoded patches |
| Conformance  | WPT corpus + chunked re-reads + fuzz | parser matches the spec, independent of TCP chunking  |
| Consumer E2E | `datastartest` in YOUR repo          | your handler emits what your UI needs                 |

## Testing your handlers with datastartest

Add the module (it is versioned separately: `datastartest/v0.x.y`):

```bash
go get github.com/larsartmann/go-datastar/datastartest@latest
```

One-liner E2E: spin up `httptest`, GET, parse SSE, decode DataStar datalines:

```go
func TestFeedHandler(t *testing.T) {
	events := datastartest.Collect(t, myFeedHandler)

	datastartest.RequireEventCount(t, events, 2)
	datastartest.RequireElements(t, events[0], "#feed", "append", "<div>hello</div>")

	var data struct{ Count int `json:"count"` }
	events[1].UnmarshalSignals(&data) // data.Count == 1
}
```

Variants: `CollectPost` (JSON body), `CollectWithRequest` (custom method +
options), `CollectN` (streaming handlers), `CollectWithTimeout` (deadlines).
Request options: `WithPath`, `WithDatastarSignals`, `WithLastEventID`
(reconnection replay), `WithHeader`.

Assert intent, not bytes, for scripts:

```go
datastartest.RequireScript(t, evt, `console.log("hi")`)
// or typed accessors:
if got := evt.RedirectURL(); got != "/next" { ... }
```

Full API tour: [datastartest/README.md](../datastartest/README.md).

## Coverage

Measured, badged, not gated — rationale in
[ADR 005](adr/005-coverage-strategy.md). Current (2026-09-03): root 98.4%,
datastartest 92.7%, static 100%. The badge on the README is generated by CI
(`coverage.yml`) from the same suite you run locally.

## Measurement ritual

Re-measure coverage and lint-cache timing whenever tooling or the test suite
changes shape, and date-stamp the numbers:

```bash
# Coverage (per-package numbers are what the docs quote):
GOEXPERIMENT=jsonv2 go test ./... ./datastartest/... ./static/... \
  -coverprofile=/tmp/cover.out -covermode=atomic
go tool cover -func=/tmp/cover.out | tail -1

# Lint cache timing (the analysis cache is the lint job's long pole):
mv ~/.cache/golangci-lint /tmp/lint-cache-old   # cold
{ time nix run .#lint-ci; } 2>&1 | grep real    # cold run
nix run .#lint-ci                                # warm run, timed again
```

Reference points (2026-09-03, desktop zen5 APU): lint cold ~17s, warm ~1.5s
locally; CI's lint job is ~1m33s cold (adds the linter install). If the warm
run exceeds ~5s locally, suspect cache corruption — move the cache aside and
re-measure.

## The commands

```bash
# Everything, with the race detector (workspace mode):
GOEXPERIMENT=jsonv2 go test ./... ./datastartest/... ./static/... -race -count=1

# Per-module isolation (what CI does too):
for mod in . ./datastartest ./static; do
  (cd "$mod" && GOWORK=off GOEXPERIMENT=jsonv2 go test ./... -count=1)
done

# Benchmarks:
nix run .#bench    # or: go test -bench . -benchmem ./... in each module
```

`GOEXPERIMENT=jsonv2` is required (transitively via go-sse).
