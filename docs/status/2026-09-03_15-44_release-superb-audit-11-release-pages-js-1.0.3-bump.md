## e) WHAT WE SHOULD IMPROVE

1. **Make the upstream-JS check a hard release step, not a quarterly suggestion.** §5's "quarterly or after upstream release" was skipped in practice within 7 days. Add an explicit `gh api repos/starfederation/datastar/releases/latest --jq .tag_name` step to the release lane.
2. **Record bundle provenance at download time.** A 3-line script (download `bundles/datastar.js@tag`, print sha256, emit the provenance comment) kills beautified-variant-style mysteries permanently.
3. **Serve only the canonical minified artifact.** Beautified variants belong in a scratch dir, never in the repo; document the policy in docs/static-js.md.
4. **Release-page creation needs per-module explicitness.** Checklist §4's single "Create GitHub Release from the tag" line was silently read as root-only for 5 releases. Spell out all three `gh release create` commands with `--latest=false`.
5. **pkg.go.dev freshness belongs in the checklist.** "Proxy correct" ≠ "docs rendered" — add a §4 step: fetch all three module pages and re-crawl stale ones. Today this cost 3 retries to diagnose.
6. **Daemon-race protocol.** During focused multi-file edits, check `git log -1` before staging; commit fast, and remember the amend window only exists pre-push. The real fix is small, fast commits.
7. **Test literals that duplicate static.Version.** `response_test.go` hardcodes `"1.0.3"`; deriving it from `static.Version` would have made the bump one touchpoint smaller (this session: 9 touchpoints, several pure version-string churn).
