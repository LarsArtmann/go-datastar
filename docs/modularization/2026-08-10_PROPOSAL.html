Modularization Proposal

go-datastar Module Boundary Refinement

Break the circular module dependency between root and datastartest by relocating the E2E integration test, eliminating the test-dep leak, and establishing a clean DAG across all three modules.

Clean Leaf

The project is a partially split Go workspace with three modules: root (protocol library), static/ (embedded JS asset), and datastartest/ (E2E test helpers for consumers). The static/ module is a clean leaf with zero dependencies. The root and datastartest modules form a circular dependency: root requires datastartest for a single E2E test file, while datastartest requires root for production code (event type constants, dataline keys).

The fix is a single relocation: move TestE2E_DataStarPatches from root's e2e_test.go into the datastartest module. This breaks the cycle, eliminates the test-dep leak, and produces a clean DAG where root depends only on static/ (production) and datastartest depends on root (production). No new modules are needed. No module merges are needed. The existing boundaries are at the right depth.

02Issues Found

FM#1 — Circular Dependency

root ↔ datastartest circular module dependency

go.mod (root), go.mod (datastartest)

The root module requires datastartest in its require block (not marked // indirect), but datastartest is only imported from e2e_test.go — a test file. Meanwhile, datastartest requires root for production code (event.go, assert.go, filter.go use datastar.* constants and types). This creates a bidirectional module dependency. Go allows this with replace directives, but it is architecturally wrong: the production library should never depend on a test helper module.

Fix Move TestE2E_DataStarPatches from root's e2e_test.go to datastartest/e2e_test.go. This test dogfoods the datastartest helpers against the root library — it belongs with the test helpers, not the production library. After the move, root no longer imports datastartest and the require can be removed.
FM#3 — Test-Dep Leak

datastartest in root's production require block

go.mod (root): require github.com/larsartmann/go-datastar/datastartest v0.1.0

go mod why -m github.com/larsartmann/go-datastar/datastartest confirms it is only needed by github.com/larsartmann/go-datastar.test (the test binary). Consumers who go get github.com/larsartmann/go-datastar transitively pull in the test helper module. This is a test-dep leak: a test-only dependency appearing in the production require block.

Fix After relocating the E2E test, run go mod tidy on root. datastartest will be removed from the require block automatically since no file imports it. The replace directive for datastartest is also removed.
FM#12 — Workspace-Only Testing

CI lacks per-module GOWORK=off isolation tests

.github/workflows/ci.yml

The CI runs go test ./... ./datastartest/... ./static/... which uses the workspace. There is no per-module GOWORK=off test step. This means version mismatches and missing replace directives would be masked by the workspace. All three modules currently build standalone with GOWORK=off, but this is not verified in CI.

Fix Add a per-module GOWORK=off build and test step to CI, verifying each module resolves and builds independently.

07Versioning Strategy

Shared versioning (single git tag bumps all modules). The project is a single-team library with tight coupling between root and static. Consumers typically import both. Independent semver would add friction with no payoff. The existing v0.1.0 internal references work correctly with replace directives.
